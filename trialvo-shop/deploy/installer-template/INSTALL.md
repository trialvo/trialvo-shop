# Install the Trialvo shop on your own host

This guide is for the **Option 2 installer ZIP** you downloaded from Trialvo (trial or paid Docker pack). Follow it on a VPS. If you received a **cPanel / Node** pack instead, see [INSTALL-CPANEL.md](./INSTALL-CPANEL.md).

You run every command. Trialvo never logs into your server.

---

## 1. Prerequisites (Docker VPS)

On Ubuntu or Debian (or any Linux VPS you manage):

1. **Docker** and **Docker Compose** (Compose v2 plugin: `docker compose`).
2. A **domain** whose DNS **A record** points at this server’s public IPv4 address. You can edit `.env` first and point DNS afterward — just wait for DNS to propagate before you expect HTTPS or public links to work.
3. **Firewall / security group** open for **80** and **443** (and the API / admin / shop ports listed in `.env` if you are not putting a reverse proxy in front).
4. Enough disk for the images and the MySQL volume (a few GB is typical).

Windows hosts can use Docker Desktop and `setup.ps1` instead of `setup.sh`.

---

## 2. Upload and unzip the installer

1. Download the ZIP from your Trialvo **trial status** page or the email we sent after approval.
2. Copy it to the server (SFTP, `scp`, or your panel’s file manager).
3. Unzip it. You should see a folder named like `trialvo-<product>-trial` or `trialvo-<product>-paid`.
4. `cd` into that folder. Keep `agent.env` next to `docker-compose.yml` — the setup script looks for it in the same directory.

Public installer links are **single-use and time-limited**. If the ZIP is lost or the link is spent, request a new installer from your status page or Trialvo support.

---

## 3. Create `.env` from the example

```bash
cp .env.example .env
```

Edit `.env` (nano, vim, or any editor). Set at least:

| Variable | What to put |
| --- | --- |
| `DOMAIN` | The hostname customers will use (e.g. `shop.yourbrand.com`) |
| `DB_ROOT_PASSWORD` | A strong database password — do not leave the example value |
| `JWTSECRET` | A long random secret for the shop’s own login tokens |
| `PUBLIC_API_ORIGIN` | Browser-facing API URL (`https://api.yourbrand.com` or `https://yourbrand.com:9000`) |
| `PUBLIC_SHOP_ORIGIN` | Browser-facing shop URL |
| `TRIAL_ADMIN_EMAIL` | Admin email from the Trialvo **status email** |
| `TRIAL_ADMIN_PASSWORD` | Admin password from that same email |

Match `PUBLIC_*` to how you will actually reach the stack (plain ports for a first test, or HTTPS hostnames behind your proxy).

---

## 4. Leave `agent.env` alone

`agent.env` is generated by Trialvo for **this** install. It holds the install id, agent secret, registry pull token, and `CONTROL_PLANE_URL`.

- Do **not** share it, commit it, or copy it to another domain.
- Do **not** edit `CONTROL_PLANE_URL` unless Trialvo asked you to. The agent on the VPS must be able to reach that URL (outbound HTTPS).
- Paid packs already have license enforcement set. Trial packs stay in trial mode until you buy.

---

## 5. Run setup

Linux / macOS:

```bash
chmod +x setup.sh
./setup.sh
```

Windows (PowerShell, in the unzipped folder):

```powershell
./setup.ps1
```

The script logs into the private image registry (using the token in `agent.env`), then starts Docker Compose.

---

## 6. First run may only create `.env`

If `.env` was missing, `setup.sh` / `setup.ps1` **copies `.env.example` → `.env` and exits**. That is expected.

1. Edit the new `.env` (domain, passwords, `PUBLIC_*`, admin email/password).
2. Run `./setup.sh` (or `./setup.ps1`) **again**.
3. Compose then starts `api`, `admin`, `shop`, `db`, and `license-agent`.

---

## 7. Point DNS and open the shop

1. Confirm the domain **A record** targets this VPS.
2. Wait until `docker compose ps` shows the containers healthy / running.
3. Open the shop URL and the admin URL from your `.env` ports or public origins.
4. Sign in to admin with the email and password from the Trialvo status email (the values you copied into `.env`).

First boot seeds demo catalog data automatically.

---

## 8. The agent registers with Trialvo

The license agent talks to Trialvo using the secrets in `agent.env`. You do not register by hand.

When the agent checks in, the own-domain trial on your **status page** becomes **Active**. If it stays “setting up”, see troubleshooting below — usually DNS, firewall, or `CONTROL_PLANE_URL` not reachable from the VPS.

---

## 9. Troubleshooting

**See what is running**

```bash
docker compose ps
docker compose logs -f
```

Check a single service, for example:

```bash
docker compose logs license-agent
docker compose logs api
```

**Firewall** — allow inbound 80/443 (and the published ports in `.env` if you expose them). The VPS must also allow **outbound** HTTPS so the agent can reach `CONTROL_PLANE_URL`.

**Control plane unreachable** — from the VPS: `curl` the `CONTROL_PLANE_URL` in `agent.env`. If that fails, the trial will not flip to Active. Corporate egress filters or a missing IPv4 route are common causes.

**Images will not pull** — `setup.sh` must have logged into the registry. Re-run setup; do not delete `agent.env`. Registry tokens are scoped to this install and expire with the trial if it is a trial pack.

**Single-use installer link** — downloading twice from the same public URL may fail. Use the status page to get a fresh ZIP.

**Wrong domain** — `DOMAIN` in `.env` and `TRIAL_DOMAIN` in `agent.env` should match the hostname you actually serve. Copying this pack onto another domain can freeze a paid license.

**Still stuck?** Email Trialvo or use WhatsApp from the contact page. Include your install id (in `agent.env` as `TRIAL_INSTALL_ID`) — not the full `agent.env` file.
